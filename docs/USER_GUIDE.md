# 用户指南

本文档介绍 Hotkey Blocker 的安装、规则管理、配置文件位置和常见故障处理方法。

## 安装与启动

从 GitHub Release 下载 x64 安装包，并在 x64 Windows 上运行 NSIS 安装程序。安装器只为当前 Windows 用户安装，不需要管理员权限，默认目录为 `%LOCALAPPDATA%\Programs\Hotkey Blocker`；开始菜单快捷方式和卸载注册信息也只对当前用户生效。目前发布包只有 x64 安装包；它同时包含 x64 和 x86 运行组件，可处理两种架构的目标进程。不要单独删除安装目录中的 Hook DLL 或 x86 辅助程序。

程序可以从开始菜单或安装目录启动。启用“登录时启动”后，程序会在当前用户登录时以后台模式启动，不需要管理员权限即可写入当前用户的启动项。

升级时直接运行新版本安装包，文件会覆盖到当前用户的安装目录，不会先运行卸载程序，也不会删除用户配置。安装器会检查 Hotkey Blocker 程序文件和 Hook DLL 是否仍被进程使用。检测到占用时，安装器会列出应用名和 PID，并提示先由用户自行关闭这些应用，再点击“重新检测”。占用清空后才会继续安装；安装器和卸载程序都不会替用户结束进程。卸载程序也会执行相同的检查流程。

如果电脑上仍有旧版全局安装（安装在 `Program Files`），首次切换到当前用户安装时，请先备份 `%LOCALAPPDATA%\HotkeyBlocker\config.ini`，再使用旧版卸载程序移除旧版，最后运行新版安装包。之后的版本可直接覆盖升级。

## 版本与更新检查

主窗口标题栏显示当前构建版本。程序启动后会在后台请求 GitHub Release 的最新稳定版本；也可以从主窗口“帮助”菜单或系统托盘菜单选择“检查更新”手动检查。检查过程不会阻塞主窗口，网络失败时自动检查保持安静，手动检查会显示错误原因。

版本检查只读取公开的 Release 元数据，不会上传规则、配置或日志；发现新版本后程序会打开对应的 GitHub 发布页面，更新包仍需由用户确认下载和安装。

## 添加规则

1. 点击“添加 EXE”，选择要限制的应用程序；或点击“添加文件夹”。
2. 文件夹规则会递归匹配其中的 `.exe` 文件。
3. 新规则默认启用。
4. 选中规则后点击“配置”，选择该应用的快捷键策略：
   - “拦截全部”：拒绝该进程后续所有标准 `RegisterHotKey` 注册请求。
   - “黑名单”：只拒绝列表中的组合键，例如 `Ctrl+Alt+A`；未列出的快捷键放行。
   - “白名单”：只放行列表中的组合键；未列出的快捷键拒绝。
5. 在“按下组合键”输入框中直接按键，再点击“添加”；`Ctrl`、`Alt`、`Shift` 和 `Win` 会按组合状态保存。
6. 如果目标应用已经运行，请退出并重新启动该应用。
7. 状态显示为“拦截已生效”后，该进程后续的标准全局快捷键注册会按当前策略处理。

黑名单为空时表示放行全部快捷键；白名单为空时表示拦截全部快捷键。修改策略不会撤销目标应用已经成功注册的快捷键，因此每次修改后都必须重启目标应用。

每个策略最多保存 128 个快捷键，重复组合键会自动去重。快捷键由 Ctrl、Alt、Shift、Win 修饰键和一个主键组成。

## 管理规则

- “启用/停用”会影响之后启动的目标应用；正在运行的应用需要重启后才能完全应用状态变化。
- “配置”只修改当前应用规则；文件夹规则下的每个目标进程使用同一套快捷键策略。
- 停用或删除规则不会关闭目标应用；正在运行的应用需要重启后才能完全恢复。
- 系统托盘菜单可以重新打开窗口或退出程序。

## 配置文件与日志

默认文件位置：

```text
%LOCALAPPDATA%\HotkeyBlocker\config.ini
%LOCALAPPDATA%\HotkeyBlocker\logs\hkb.log
```

配置和日志保存在本机。日常操作请通过“配置”窗口管理快捷键策略。卸载程序默认保留配置和日志；如需一并删除，可在卸载器中勾选“删除配置文件和日志”。日志最多保留当前文件和两个轮转文件；提交日志时请隐藏用户名、项目路径和其他敏感信息。

## 兼容性限制

Hotkey Blocker 只针对标准 `RegisterHotKey` API。以下情况可能无法处理：

- 应用使用低级键盘钩子、驱动或自定义窗口消息实现快捷键。
- 目标进程以管理员或 SYSTEM 权限运行，而 Hotkey Blocker 以较低权限运行。
- 目标进程是受保护进程、使用反注入策略或启用了动态代码限制。
- 目标应用为 ARM64，或安装文件缺少相应组件。
- 目标应用在规则生效前已经启动并注册快捷键；请重启该应用。

## 故障排查

### 目标应用仍然能够使用快捷键

确认规则已启用，关闭目标应用的所有进程后重新启动。若仍无效，它可能没有调用标准 `RegisterHotKey`，或者存在更高权限、反注入或安全软件限制。

### 状态显示“重启程序后生效”

这表示程序发现目标进程已经在运行。重启目标程序后再观察状态。

### 状态显示“启用拦截失败”

打开 `%LOCALAPPDATA%\HotkeyBlocker\logs\hkb.log`，查看错误码。优先检查目标应用和本机的架构是否匹配、权限是否足够、安装文件是否完整，以及安全软件是否拦截了程序。

### 恢复全部设置

退出 Hotkey Blocker 后，将 `%LOCALAPPDATA%\HotkeyBlocker\config.ini` 备份到其他位置，再删除该文件。下次启动时程序会创建空配置。删除配置不会立即恢复正在运行的目标应用；这些应用仍需重启。

## 安全提示

程序需要在目标应用中执行本地快捷键拦截，因此安全软件可能将其识别为注入行为。只从可信来源下载发布包，并校验 Release 中提供的 SHA-256 文件。详见 [SECURITY.md](../SECURITY.md)。

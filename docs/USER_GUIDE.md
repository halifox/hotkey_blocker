# 用户指南

本文档介绍 Hotkey Blocker 的安装、规则管理、配置文件位置和常见故障处理方法。

## 安装与启动

从 GitHub Release 下载与系统架构匹配的安装包，运行 NSIS 安装程序。x64 安装包同时包含 x64 和 x86 运行组件；不要单独删除安装目录中的 Hook DLL 或 x86 辅助程序。

程序可以从开始菜单或安装目录启动。启用“登录时启动”后，程序会在当前用户登录时以后台模式启动，不需要管理员权限即可写入当前用户的启动项。

## 添加规则

1. 点击“添加 EXE”，选择要限制的应用程序；或点击“添加文件夹”。
2. 文件夹规则会递归匹配其中的 `.exe` 文件。
3. 新规则默认启用。
4. 选中规则后点击“配置”，选择该应用的快捷键策略：
   - “拦截全部”：拒绝该进程后续所有标准 `RegisterHotKey` 注册请求。
   - “黑名单”：只拒绝列表中的组合键，例如 `Ctrl+Alt+A`；未列出的快捷键放行。
   - “白名单”：只放行列表中的组合键；未列出的快捷键拒绝。
5. 在“按下组合键”输入框中直接按键，再点击“添加”；`Ctrl`、`Alt`、`Shift` 和 `Win` 会按组合状态保存。
6. 如果目标应用已经运行，请退出并重新启动该应用。
7. 状态显示为“全局快捷键注册拦截已生效”后，该进程后续的标准全局快捷键注册会按当前策略处理。

黑名单为空时表示放行全部快捷键；白名单为空时表示拦截全部快捷键。修改策略不会撤销目标应用已经成功注册的快捷键，因此每次修改后都必须重启目标应用。

## 管理规则

- “启用/停用”只影响后续注入和之后启动的目标进程。
- “配置”只修改当前应用规则；文件夹规则下的每个目标进程使用同一套快捷键策略。
- 已经加载 Hook 的进程不会被强制卸载 DLL；停用后需要重启目标应用才能完全恢复。
- 删除规则不会终止目标进程。
- 系统托盘菜单可以重新打开窗口或退出程序。

## 配置文件与日志

默认文件位置：

```text
%LOCALAPPDATA%\HotkeyBlocker\config.ini
%LOCALAPPDATA%\HotkeyBlocker\logs\hkb.log
```

配置文件使用 UTF-8 INI 格式。修改配置前建议退出程序并备份文件。日志最多保留当前文件和两个轮转文件；提交日志时请隐藏用户名、项目路径和其他敏感信息。

## 兼容性限制

Hotkey Blocker 只针对标准 `RegisterHotKey` API。以下情况可能无法处理：

- 应用使用低级键盘钩子、驱动或自定义窗口消息实现快捷键。
- 目标进程以管理员或 SYSTEM 权限运行，而 Hotkey Blocker 以较低权限运行。
- 目标进程是受保护进程、使用反注入策略或启用了动态代码限制。
- 目标进程架构不属于 x86/x64，或安装包缺少对应的 Hook DLL。
- 目标应用在注入前已经注册快捷键；请重启目标应用。
- 目标应用调用 `RegisterHotKey` 时传入的 `MOD_NOREPEAT` 不参与黑名单/白名单匹配；例如 `Ctrl+Alt+A` 与带 `MOD_NOREPEAT` 的同一组合键视为相同快捷键。

## 故障排查

### 目标应用仍然能够使用快捷键

确认规则已启用，关闭目标应用的所有进程后重新启动。若仍无效，它可能没有调用标准 `RegisterHotKey`，或者存在更高权限、反注入或安全软件限制。

### 状态显示“目标程序需重启”

这表示程序发现目标进程已经在运行。重启目标程序后再观察状态。

### 状态显示“拦截功能启用失败”

打开 `%LOCALAPPDATA%\HotkeyBlocker\logs\hkb.log`，查看错误码和目标 PID。优先检查架构、权限、拦截组件是否完整，以及安全软件是否拦截了注入。

### 恢复全部设置

退出 Hotkey Blocker 后，将 `%LOCALAPPDATA%\HotkeyBlocker\config.ini` 备份到其他位置，再删除该文件。下次启动时程序会创建空配置。删除配置不会自动卸载已经注入到正在运行进程中的 Hook；这些进程仍需重启。

## 安全提示

程序需要向目标进程加载本地 Hook DLL，因此安全软件可能将其识别为注入行为。只从可信来源下载发布包，并校验 Release 中提供的 SHA-256 文件。详见 [SECURITY.md](../SECURITY.md)。
